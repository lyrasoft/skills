# 夏木樂（Simular）共用 AI 指示庫

這個專案是夏木樂（Simular）也是 LYRASOFT 的全公司共用 agent 指示庫，目的是集中管理跨專案可重用的 AI 指示、工作規範、流程說明與知識模板，讓各部門、各專案都能依循一致的標準進行協作。

## 公司與專案簡介

- 夏木樂（Simular）是 LYRASOFT 的公司內共用 AI 協作與知識基礎設施，強調標準化、可複用與跨專案一致性。
- 本倉庫作為公司層級的共用指示庫，提供 AI Agent、開發者與協作成員可直接引用的規範與模板。
- 內容以公司級共用知識為主，避免個別產品、專案或敏感資訊干擾通用性。

## 夏木樂專案標準

- 以 Markdown 為主要資料格式，確保易讀、易複製、易分享。
- 連結到其他檔案時，優先使用 `[顯示文字](相對路徑)`；只有單純提及檔名或檔案類型時才使用反引號。
- 所有內容優先保持通用、可重用、可跨專案適配。
- 避免加入產品機密、使用者資料、金鑰、帳號、部署設定或其他敏感資訊。
- 內容應以簡潔、模板化、可執行的方式整理，方便後續直接套用於新專案。
- 專案中除開頭簡介外，後續主要實體與內容以「夏木樂」為主要命名與描述主體。

## 目的

- 整合公司共用的技能、流程與 AI 指示
- 提供一致的文件結構與工作標準
- 讓不同專案能快速吸收既有經驗與規範
- 保持知識庫可維護、可再利用、可擴充

## 命名與檔案規範

這個倉庫依照 GitHub Copilot 官方建議，將不同型態的內容明確分開：

- `README.md`: 這個資料夾或專案的總覽、目的與索引；適合放介紹與入口資訊。
- `AGENTS.md` / `.agents/main.instructions.md`: repository-level 的工作規則、風格與限制，面向協作者與 AI agent。
- `SKILL.md`: 單一可重用技能的定義，說明適用時機、預期行為與驗證方式；適合放在技能層級。
- `*.prompt.md`: 可重用的 prompt 模板，讓 AI 能直接使用特定任務指令。
- `files/docs/` 與 `files/skills/`: 文件與技能的內容集合，不是整體專案入口。

注意：如果內容是「技能定義」，應優先使用 `SKILL.md`，不要用 `README.md` 取代。`README.md` 保留給總覽與目錄說明。

另外，`files/` 目錄內的內容不應反覆出現公司名稱；除非特別指定，應以中性、通用的語言描述，避免任何地方都寫死公司品牌名。

## 語言與區域版本

這個倉庫提供兩種語言版本的共用工具集：

- `files/zh-TW/`: 中文版本，適合中文團隊與中文專案使用
- `files/en/`: 英文版本，適合英文團隊與國際協作使用

這些內容都可視為可複製到 `.github/` 的工具組，讓不同專案與團隊根據需求選擇中文或英文。若沒有明確要求特定語言，通常以中英文同時編寫為預設原則，避免只保留單一語言造成後續維護差異。

## 結構

- `README.md`: 專案總覽、公司背景與使用標準
- `AGENTS.md`: 提供協作者與 AI agent 的基本指引
- `files/`: 可複製到 `.github/` 的通用工具集，包含 `zh-TW/` 與 `en/` 兩個語言版本
- `files/instructions/`: repo-level 指令與規則分流說明
- `files/skills/`: 可重用技能與模板集合
- `files/docs/`: 內部文件與文件範本
- `files/prompts/`: AI 輔助工作所需的 prompt 模板

## 使用規則

- 保持內容以 Markdown 編寫
- 優先使用通用語言，不加入專案私有實作細節
- 以模板與清單方式整理，避免冗長敘述
- 不新增執行時程式碼、建置工具或專案特定設定
- 由夏木樂維持公司共用知識庫的命名與資訊風格一致

## 預期用途

這個倉庫適合作為夏木樂內部跨專案的共用知識庫，用於保存公司指引、協作規範、文件模板與 AI 工作指示，讓所有專案都能依循同一套標準。
