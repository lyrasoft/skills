# Copilot 指引

## 專案定位

這個專案是夏木樂（Simular）與 LYRASOFT 的全公司共用 agent 指示庫，提供跨專案、跨部門可重用的 AI 工作規範、協作說明與文件模板。內容以公司共用知識的角度整理，並以夏木樂為主要命名與敘述主體。

目標：

- 保持跨專案協作的一致性
- 讓新專案、團隊與 AI agent 能快速套用既有標準

## 內容範圍

適合放置：

- 跨專案可重用的技能與作業說明
- 公司內部文件模板與慣例
- AI prompt 模板與通用工作指引
- 團隊 onboarding 與專案初始化的標準流程

不要放置：產品實作文件、應用程式原始碼、部署腳本、機密資訊或敏感設定。

## 本專案使用結構

- @../README.md：專案總覽與共用標準入口
- @../AGENTS.md：協作者與 AI agent 的基本指引
- 本專案內的 `.agents/` 才是可參考的執行文件。
- `files/zh-TW/`、`files/en/`：中文與英文兩個共用版本，可複製到各專案的 `.agents/` or `.github/`

### 提供給外部專案之文件

- `files/*/instructions/`：repository-level 規則與內容分流說明
- `files/*/skills/`：共用技能與模板
- `files/*/docs/`：公司內文件與說明範本
- `files/*/prompts/`：AI 工作流程 prompt 模板
- `review/`：審查規則與文件（`REVIEW.md`、`instructions/`、`docs/`）

> [!important]>
> `files/**` 與 `review/**` 內的內容是為了讓其他專案的 agent 使用的，不應該對本專案的程式碼或測試產生影響

## 檔案命名與角色

以下檔案可能存在任何目錄中，用於指引該目錄內相關的規則與操作：

- `README.md`：入口、總覽與索引
- `AGENTS.md` AI 與協作者的作業規則與限制
- `SKILL.md`：單一技能的定義、目的、適用時機、預期行為與驗證；技能內容不要寫成 `README.md`
- `*.prompt.md`：可重用 prompt 模板
- `docs/`、`skills/` 等資料夾：說明文件、模板與技能內容，不是入口文件

## 語言

- 同時維護中文（`files/zh-TW/`）與英文（`files/en/`）版本
- 未另行指定時，採用中英文同時編寫；使用者明確要求單一語言時依其指定
- `files/` 內容避免反覆出現公司名稱，使用中性、通用的說法

## 長文件載入

`docs` 內的長文件依「需要時才載入」原則處理，不要一次讀完整個資料夾：

- 先讀 `files/*/docs/index.md` 取得文件總覽與分段入口
- 創建或修正文件時，再載入 `files/*/docs/templates/`
- 新增 docs 類別時，同步更新 `docs/index.md` 的分類說明

## 編輯原則

- 內容僅以 Markdown 管理
- 檔案連節:
  - 重要的檔案連或指引，使用 `@相對路徑` 格式
  - 需要搭配標題時，可用 markdown 格式: `[顯示文字](相對路徑)` 連結
  - 一般敘述中提及檔案可依語境決定是否連結，單純提及檔名或檔案類型時使用反引號
- 優先使用通用、可重用、可適配的語言，不依賴單一產品背景
- 保持模板簡潔、可直接複製到其他倉庫
- 避免加入特定客戶、產品或部門資料，除非作為範例明確需要
- 維持清楚的資料夾職責，避免無關內容混雜
- 避免敏感資訊、產品機密、部署設定與金鑰

## 新增內容檢查

- 與公司級共用知識相關
- 可跨專案重用，語意清楚，其他團隊或 AI agent 可直接套用
- 符合夏木樂共用指示庫的標準格式與風格
